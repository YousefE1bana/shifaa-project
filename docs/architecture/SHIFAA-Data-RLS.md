# SHIFAA Data and RLS Contract

> **Version:** 1.2.0 · **Status:** Proposed normative logical baseline · **Last verified:** 2026-08-13
> Seeded-synthetic physical DDL now exists for features 001–004. Production infrastructure and formal approval remain governed by the canonical open items, including `OPEN-TECH-002` and `OPEN-SEC-001`.

## 1. Global conventions

- PostgreSQL 17; schemas are private from `anon`/`authenticated`; only the API execution role receives table privileges.
- PK is `id uuid default gen_random_uuid()`. Every mutable row has `created_at timestamptz`, `updated_at timestamptz`, and `version integer default 1 check (version > 0)` unless explicitly append-only.
- Actor references use `auth.users(id)`. Patient references use `identity.patients(id)`. Facility references use `identity.facilities(id)`.
- Codes are `text` with checks or reference tables; timestamps are UTC `timestamptz`; dates are `date`; money is `amount_minor bigint` plus `currency char(3)`; quantities are `numeric` plus `unit_code text`.
- Append-only tables reject `UPDATE`/`DELETE`. Versioned records are superseded by a new row linked through `supersedes_id`.
- Domain deletes are state transitions/pseudonymization, never cascading deletion of clinical, finance, consent, or audit history.
- The API transaction sets `app.actor_id`, `app.facility_id`, `app.purpose_code`, `app.aal`, and `app.request_id` from verified server state. Client headers cannot set them.

## 7. State-machine invariants

- State changes occur only through named database functions invoked by the API repository; direct table state updates are revoked.
- Terminal emergency-contact states cannot transition. Re-invitation creates a new row.
- Signed prescriptions are immutable; cancellation/supersession appends events and versions.
- A contraindicated issue needs a valid, unexpired override with required independent signatures before `signed`.
- Inventory balance equals movement sum and stays between zero and pack total except an audited correction transaction.
- One active bed assignment per bed and one active bed assignment per admission.
- Released lab results are immutable; correction creates `corrected` linkage.
- Approval actor differs from originator for governed resources.
- Admin-role removal requires a pending revocation request and an independent `super_admin` decision; direct active-to-revoked updates are denied.

## 9. Audit event contract

Every sensitive read and every mutation emits: `id`, `occurred_at`, `request_id`, `trace_id`, `actor_user_id`, `actor_person_id`, `authentication_aal`, `facility_id`, `patient_id`, `purpose_code`, `action_code`, `resource_type`, `resource_id`, `resource_version`, `outcome`, `reason_code`, `source_ip_prefix`, `user_agent_class`, `previous_hash`, and `event_hash`. Payload values and clinical free text are excluded.

## 10. Index and concurrency requirements

- Index every FK used for authorization, active-status partial predicates, appointment time lookup, product GTIN/serial, bed availability, lab accession, outbox readiness, and audit time partition.
- PostGIS GiST indexes facilities; blind indexes use unique B-tree; search uses approved GIN/trigram projections.
- Booking uses exclusion/unique constraints and serializable or retryable transaction logic.
- Bed/inventory/catalog/schedule mutations require the catalogued version/`If-Match`; zero-row update is `409`.
- RLS tests exercise concurrent revocation/token staleness and do not rely solely on JWT role metadata.

## 11. Retention classes

Every row/object references one of: `IDENTITY_PROOF`, `CLINICAL_RECORD`, `PRESCRIPTION_DISPENSE`, `LAB_RECORD`, `CONSENT_EVIDENCE`, `SECURITY_AUDIT`, `FINANCE_RECORD`, `COMMUNICATION`, `SOS_LOCATION`, or `TRANSIENT_TECHNICAL`. Durations and post-expiry actions remain unset until OPEN-LEGAL-002 supplies a signed Egyptian retention schedule. Specs may define shorter transient/cache periods but cannot invent statutory medical retention.

## 12. Feature 005 privacy/notification realization

- DSR/event/assignment/export-capability and notification governance/delivery tables use forced RLS. Subject access is self or active guardianship plus `consent.manage`; delegation and facility membership are denied.
- DPO access composes a current designation, AAL2, `privacy.dsr.review`, and active exact-request assignment. The API performs a current-fact preflight and RLS independently rechecks it.
- Export objects remain private; capability plaintext is never persisted, the digest is person-bound, and issuance/consumption are limited to five minutes and once.
- `shifaa_worker` is a dedicated `NOBYPASSRLS` role. It may read published releases, claim/update minimum notification metadata, and append delivery attempts; it cannot delete or directly read DSR/export data.
- Statutory retention and production erasure/pseudonymization automation remain absent under `OPEN-LEGAL-002`.
