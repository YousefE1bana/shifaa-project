## Inventory method and authority

The tracked Git tree is the inventory basis: docs/specs/SpecKit/owned skills/Codex/runbooks/workflows plus documentation anywhere in the repository and generated contract surfaces. Sources and scripts are examined to resolve concrete operational discrepancies. Immutable spec evidence receives path/blob/hash/group classification; this does not imply semantic inspection of thousands of historical logs. Detailed inspection targets entry points, authority clauses, approval/activation records, current contracts, integration metadata, verifiers and the changes identified in the drift register.

Classifications describe the item's role at this base, with unresolved/partial applicability in its issue/action field. CURRENT_CANONICAL does not mean every claim within a document is newly verified. A frozen current source may require an additive lookup for a bounded successor. HISTORICAL_IMMUTABLE never means obsolete evidence should be removed. DRAFT_OR_PROPOSED is preserved where no later approval resolves it. No status word is globally replaced.

The baseline has 5,621 tracked files. The inventory reports its exact subset and counts in validation-results; build trees, dependencies and local ignored/private material are excluded from publication. Candidate files are listed separately from the predecessor inventory. OPEN IDs, canonical requirement vocabulary and all original approval/hash records remain unchanged.
