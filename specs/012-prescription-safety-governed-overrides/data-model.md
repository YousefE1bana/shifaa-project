## 1. Types, protection and identity

Unless marked `?`, fields are NOT NULL. PK/FK identifiers are UUID; version fields are positive int32; timestamps are UTC `timestamptz`, transport RFC 3339. Hashes are exact 32-byte SHA-256, transport lowercase 64 hex. Quantities are positive arbitrary-precision numeric with explicit unit code, carried as decimal strings to avoid floating-point loss. Text/codes are checked closed values or referenced immutable coding, never free-text-only product identity. Constraints reject cross-patient/encounter/facility links. Identity FKs reference existing `identity.people`, `identity.patients`, `identity.facilities` and `auth.users`; account-to-person is resolved server-side at use. Roster cannot create a person or credential.

Mutable aggregate rows: `id, version, created_at, updated_at, retention_class`. Append records: `id, created_at, retention_class`, immutable resource/version binding and no UPDATE/DELETE. All FKs to clinical/history/evidence are RESTRICT, not cascade. Designated free-text rationale/monitoring/indication/signature/receipt payloads use a field/resource/version-bound clinical payload protection adapter preserving exact UTF-8 bytes, random nonce, key reference, ciphertext and authentication tag; no identity normalization, identity blind-index reuse, raw SQL/log/outbox payload or plaintext key. Existing F011 protection/receipt patterns are references, not permission to copy protected material or claim adapter compatibility. Production key custody/retention remains gated. Synthetic identifiers/neutral text only.

Each field group named `protected_X` expands to `X_contract_id text`, `X_key_ref text`, `X_nonce bytea`, `X_ciphertext bytea`, `X_auth_tag bytea`, all NOT NULL when the logical value exists; an optional group is either entirely absent/null or entirely present, enforced by a check constraint. Reference/ID fields are UUID except declared external source/approval identifiers, which are bounded text; source versions are external strings, F012 aggregate versions int32. State/code/contract/unit fields are text with the listed closed checks; sequence numbers are positive bigint; stored digests are bytea with length=32. Required clinical payload arrays/codings retain their exact typed contract inside protected payloads. No generic untyped JSON is an authorization surface.

## 3. Evidence digest versus concurrency

`clinicalEvidenceDigest = SHA256(canonical prescription revision + sorted required source revision/scope/completeness/freshness facts + exact approved mechanism context/manifest/input digests)`. Canonicalization proposal: existing deterministic JSON contract encoding, UTF-8, sorted object keys, decimal strings and explicit absent/null distinctions; exact cross-language golden vectors require later acceptance. Capture time is provenance, not a guessed freshness interval. A changing source-set token must be producer-authoritative, not a timestamp invented by F012.

`relianceDigest = SHA256(clinicalEvidenceDigest + immutable request identity/payload digest + lane identity + own assignment identity/revision + own designation identity/version + original roster binding)`. Store immutable exact decision bindings. Current G revalidates the same designation's continued eligibility; an unrelated roster revision requires current roster CAS on the next mutation, not a fabricated clinical-evidence change. Revocation/material designation change denies reliance. Global request CAS is NOT part of clinicalEvidenceDigest; opposite-lane actions advance request.version, not another lane's evidence/approval. Raw aggregate versions must nevertheless match on each mutation.

### Emergency truth function (ordered rules, all combinations)

The [approved truth table](spec.md) §14 remains binding. Evaluate terminal/current guards first, then the following at the transaction's validation point. These rules cover window active/expired × request live/terminal × pharmacist pending/approved/rejected × second pending/approved/rejected × sign committed/not committed (72 combinations); unstarted clock is handled separately. Existing signed history is never undone by a later predicate failure.

| Priority | Predicate                                                                    | Next sign / review outcome                                                                                                                                                                     |
| -------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | Request terminal, any other inputs                                           | No new sign/claim/decision; preserve signed or unsigned history and blocked unreviewed obligation.                                                                                             |
| 2        | Live, either lane rejected                                                   | No next sign; current rejection makes request terminal; no reopening.                                                                                                                          |
| 3        | Live, second pending                                                         | No emergency sign regardless pharmacist approval; pharmacist own review may occur while live.                                                                                                  |
| 4        | Live, second approved, pharmacist approved                                   | Next separate simulated sign may pass other G whether window active/expired; expiry is not extended/reset. Current pharmacist approval supplies the next gate, not substitute second approval. |
| 5        | Live, second approved, pharmacist pending, window active                     | Separate simulated sign may pass other G; durable pharmacist obligation remains pending.                                                                                                       |
| 6        | Live, second approved, pharmacist pending, window expired                    | No further simulated sign/continuation; current pharmacist review may advance only a still-live valid case.                                                                                    |
| 7        | Sign already committed in any above row                                      | No implicit second sign; immutable original remains; apply current guard to future action/reliance, not historical mutation.                                                                   |
| 8        | Inconsistent physical combination, e.g. active clock without second approval | Fail closed and record minimum integrity failure; do not invent approval or restart clock.                                                                                                     |

Unstarted/live/second pending allows only current lane review. Second approve can start the first window only under all original guards, including no pharmacist rejection. Delivery never starts clock or counts as review. At equality with virtual end the window is expired. No professional facility timing is chosen here.

## 6. RLS and field disclosure

Proposed tables retain ENABLE/FORCE RLS; online API uses existing `shifaa_api` non-owner, no BYPASSRLS/service-role/owner. Direct state UPDATE/DELETE denied; narrow named repository functions require validated transaction context and exact operation, not a general dispatcher usable to invent actions. ## 7. API/replay/events and transport policy proposals

Wire DTOs are [OpenAPI](contracts/openapi.yaml). All nine mutations require idempotency. Exact V set is update/check/decide/sign/cancel/R2 (six total); create/ack/request retain I only. R1/list/get are reads. If-Match is quoted positive request or prescription version as mapped in research B2. Body evidence/assignment/roster bindings are independent. Idempotency scope = internal actor ID + operation route/resource identity + key; canonical method/path/body hash. Same body authorized retry recovers exact committed status/allowed headers/bytes; changed body 409; in-progress 409 with retry advice. Key/body comparisons do not disclose historical payload after authority loss. A missing/failed lookup never proves no commit. Proposed F012 clinical receipts retain their original binding and are excluded from generic expiry deletion; no new key-retention duration is invented.

| Event proposal                  | Atomic source / minimum payload                                                                     | Ordering / consumer                                                                                     |
| ------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `f012.prescription.changed.v1`  | Committed create/update/check/sign/cancel; opaque record/revision/facility/status/event ID only     | Per-prescription sequence; no items/patient/free text. Existing authorized read required on navigation. |
| `f012.override.changed.v1`      | Request/assignment/decision/invalidation; opaque case/facility/lane/state/request revision/event ID | Per-request sequence, deterministic dedup key event ID. No patient/medicine payload.                    |
| `f012.pharmacist.obligation.v1` | Emergency request creates durable obligation before send; opaque case/lane/status                   | Existing eligible recipient scope only; R1 durable queue independent of delivery.                       |

No new channel or approved template claimed. Default external delivery disabled until an existing approved versioned template/channel is selected; durable R1 metadata remains primary recovery. Reuse the [existing retry decision policy](../../packages/core/src/privacy-dsr-notifications/policy.ts#L276): transient attempt delays 1 minute, 5 minutes, 30 minutes, 2 hours, 12 hours with bounded ±10% jitter, then dead-letter on exhaustion; permanent/schema/auth failure dead-letters immediately. Proposed lease is 30 seconds, matching the [existing F010 worker lease](../../services/worker/src/feature-010-realtime.ts#L5). This selects existing transport behavior rather than replacing platform retry policy. Aggregate sequence gaps defer later delivery, do not reorder domain effects. Escalate metadata-only failed delivery immediately to existing operational observation; pending-review age warning at 5 minutes and request expiry to API on-call/QA in isolated exercises. These are engineering observation thresholds, not clinical response deadlines. Recipient resolution rechecks exact lane/facility/authority; worker never gains patient browsing or a clinical transition. Existing platform dead-letter replay capability may append delivery attempt under its own authority; it is not F012 operation thirteen.
