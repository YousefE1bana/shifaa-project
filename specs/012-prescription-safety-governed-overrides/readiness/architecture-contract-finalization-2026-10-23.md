## 3. Final database fence proposal: A-DB

**TECHNICAL_DESIGN_PREPARED; exact acceptance required.** Alternative A is selected for all authoritative same-PostgreSQL participants. B would need an uncontracted cross-service reservation/recovery protocol; C/repeated reads prove historical or bounded results, not current-set protection. Neither substitutes for A or resolves native Auth. [Architecture 70/89](../../../docs/architecture/SHIFAA-Architecture.md#L70) permits cross-module application transactions and prohibits external calls under transactional locks.

### 3.1 Physical identity, locks and collection ownership

Select a **durable row fence**, not a hashed advisory key: proposed `platform.f012_source_admission` has one immutable deployment UUID primary key and an immutable admission-epoch UUID. Its row is provisioned before exposure; absent/multiple/wrong-deployment/unknown epoch denies. No online request creates or repairs it. All relevant DB writers and evidence-reliant F012 mutations take `FOR UPDATE`; complete captures take `FOR SHARE`. The mode is selected at transaction start, with no upgrade. The single deployment row deliberately serializes bounded synthetic writes and prevents empty-set/unknown-scope phantom gaps. Unrelated deployment fences must never be substituted.

Proposed `clinical.safety_source_generations` owns one non-null positive bigint generation per `(deployment_id, admission_epoch, producer_key, scope_key, contract_version)`. A generation has no clinical meaning. It advances once per effective collection-changing transaction; overflow/unknown identity fails, never wraps. Producer/scenario contract defines the scope and projection; clients cannot choose a narrower filter and call it complete. Authority-only mutations still take exclusive admission even when no collection generation changes. Rollback changes neither domain nor generation. Restore disables exposure, starts a new admission epoch, invalidates old captures and re-admits writers; old opaque receipts remain original history, not new clearance.

### 3.2 Complete capture and evidence envelope

Select **producer-internal complete capture in one authoritative transaction**. Do not amend the public F011 cursor or claim its separate per-page transactions yield current complete coverage. A capture starts shared admission; its producer verifies the caller's original read authorization, enumerates the declared collection with deterministic internal keyset batches on that same connection, and returns one immutable captured manifest only after reaching the declared end. A bounded resource/statement limit aborts capture as incomplete, never returns a “complete” truncated set. No count or continuation token proves completeness without this protocol.

The stored, non-public envelope is closed and contains: deployment/epoch; producer and contract version; patient or catalog scope; exact projection/status/coverage declaration; generation; ordered immutable member identity/revision/projection digest; declared total and end-reached flag; capture timestamp; source-update timestamp only if actually supplied; source freshness/completeness state; relevant eligibility interval/boundary; accepted scenario identity/version/digest where required; manifest digest. Canonical hashing follows the existing F011 digest convention. Optional unavailable timestamps are absent with freshness-unknown, not fabricated or null-as-current. Zero members is valid technical empty proof only after full capture and producer initialization; D1 additionally needs explicit approved zero-history scenario. A complete API response is not complete clinical evidence. Overall real assessment remains `not_fully_checked`.

Select an initial **technical acceptance proposal** of at most 10,000 enumerated members per declared producer scope and five seconds total capture elapsed database time, including waits, with the existing two-second lock-wait ceiling as an upper bound. These are bounded exercise resource limits, not source-derived clinical limits or performance PASS; later profiling may require a separately reviewed lower limit/optimization. On exhaustion, abort the capture/owning required mutation, preserving prior committed draft/history; never silently truncate, page a new transaction or downgrade a signing prerequisite. The accepted API NFR latency targets still apply independently. This closes the budget choice for review rather than leaving it hidden in implementation.

At later mutation, exclusive admission compares the exact envelope identity/generation plus current heads/eligibility and independent aggregate CAS. Generation equality does not eliminate clock-driven changes: re-evaluate all relevant effective/expiry predicates, including a formerly future content release becoming effective without a write. Recompute the selected permitted content manifest against current authoritative rows; a changed selected set invalidates old reliance. A status metadata read cannot authorize execution of a protected rule. Missing approved mechanism input denies simulation signing.

Stale replicas, network-only producer results, unbound pages and unadmitted writers cannot supply guarded evidence. Changed evidence requires existing current check/update/fresh linked request paths; never silently rebind an old acknowledgement/decision. No new public operation or draft-save fallback.

### 3.3 Transaction, ranks, isolation and linearization

Select PostgreSQL **READ COMMITTED**, explicit admission/row locks and same-connection application ports, not an assumed nested transaction or distributed transaction. The admission-lock statement completes before fresh authoritative source/authority reads; cached/pre-lock reads never decide admission. Fresh reads after waiting observe the preceding committed writer. No `SKIP LOCKED` for safety evidence. Existing F011 adapters' [separate callbacks](../../../services/api/src/adapters/postgres/feature-011-allergies.ts#L132) need future explicit composition; [identity transaction reuse](../../../services/api/src/adapters/postgres/identity-repository.ts#L48) demonstrates a local pattern, not universal existing composition.

Chosen DB order is: admission row → exact idempotency scope → generation rows in producer/scope order → F011 series advisory guards/domain rows in [existing ranks 2/3](../../011-allergies-clinical-content-governance/data-model.md#L188) → F012 prescription/predecessor UUID ascending, then request/lane/assignment rows → existing encounter, workforce, relationship/patient/person, consent/participant, governed-authority ranks 4–8 → append audit/outbox/obligation/receipt and complete key at rank 9. Read-only capture takes shared admission and only compatible reads/authority-share locks; never performs source mutation, idempotency mutation or upgrades. Immutable capture is persisted later only after exclusive revalidation. A new late-discovered lower-rank dependency aborts/restarts; no opportunistic lock inversion.

The coarse exclusive admission serializes participating mutations even where predecessor writers have differing internal orders. Captures may overlap; their permitted authority SHARE locks do not conflict with each other, and writers cannot enter while captures retain admission. Any pre-admission lock acquisition, trigger/callback or unclassified bypass breaks this argument and fails implementation admission. Existing F011 rank orders are preserved within each participant, with admission explicitly added before them. Native locks are deliberately **not inserted into this graph without N-1 compatibility**.

The guarded conditional domain write after current authority/evidence/CAS checks is the logical action linearization point. Use fresh database action time immediately before that write, not transaction-start or client time; effective-from inclusive, expiry equality denied, respecting source-specific date semantics. Recheck deadlines before receipt completion/commit preparation and roll back if reached. Locks stay through commit. If revocation/source change wins admission first, action rejects; if action wins and commits, its historical effect remains and subsequent actions reauthorize. Time passing after the final check does not retroactively mutate a committed historical decision. No physical WAL-commit-before-deadline guarantee is asserted; existing requirements specify current guarded action, and no stronger physical-commit timestamp clause was identified. The virtual 60-second mechanism clock remains separate and unextended.

Domain/signature/lineage/P3 records, emergency obligation, minimal audit/outbox, protected canonical response and completed original key form one transaction with deferred consistency constraints. Pre-lock preparation may resolve local crypto capability; no external Auth/producer/KMS HTTP under locks. Required producer/crypto/audit/outbox/receipt failure rolls back all new effects. Deadlock, lock timeout or serialization failure aborts the transaction; retry the same actor/key/body only after fresh admission and authority/evidence checks. Never extend request/assignment/window or assume a timeout proves rollback. After uncertain commit, reconcile original key; an authorized completed receipt returns original status/body/headers without re-emission. Current disclosure authorization is still required; history is not present clearance. Previous committed drafts, signatures, obligations and history survive failed attempts.

## 6. N-1: precise remaining native-authority design gap

Existing selected factor serialization is not all GoTrue writers. The locally pinned Supabase CLI 2.113.0 is not an exact Auth server writer/source manifest.

**What is missing before accepting an end-to-end fence:** the precise pinned native invalidation protocol: authoritative session/factor/recovery/user-ban facts; exact native writer statements and transaction/lock order for logout/global logout, refresh-family revocation, factor removal/downgrade, recovery and user disablement; the supported non-owner authority-read/lock interface and its privilege/trust boundary; compatibility with local rank zero; absence/insertion handling; and the point at which native revocation becomes effective relative to the guarded F012 effect.
