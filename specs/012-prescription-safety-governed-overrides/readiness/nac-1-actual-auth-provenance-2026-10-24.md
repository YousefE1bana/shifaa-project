1. F012 checks an unbanned actor, sees an existing AAL2 session and retains only that session row.
2. Native administrator invokes the existing ban path. `User.Ban` updates `auth.users.banned_until` and commits; it need not touch the protected session.

4. F012 relying only on its earlier user check/session guard can commit after that native ban. A retained session lock alone cannot establish the required current-authority fence.

This is an actual source-supported conflicting-authority gap, not a missing runtime race test. Adding a retained user guard can address this specific counterexample; this receipt does not imply that doing so alone proves every other row.
