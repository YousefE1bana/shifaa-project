## F011 server-side content-consumption contract — unresolved

F011 owns clinical-content release governance and protected immutable material. F012 would own prescription safety evaluation. Existing interfaces do not establish authority for that consumer:

- [F011 projection contract](../../011-allergies-clinical-content-governance/contracts/governance-boundaries.md#L17-L23) limits rule/code/test-vector bodies to explicitly authorized governance/assigned-review DTOs. Clinic status excludes them. [API list composition](../../../services/api/src/modules/feature-011/list-clinical-content.ts#L110-L145) routes status to metadata and authorized review to material resolution, then rechecks context/projection after resolution.
- [Material resolver](../../../services/api/src/modules/feature-011/artifact-review.ts#L8-L50) binds exact release/artifact references and digest; resolving bytes is not a new consumer permission. [SQL adapter](../../../services/api/src/adapters/postgres/feature-011-content.ts#L19-L45) calls the narrow authorized list function, not unrestricted table lookup. Neither grants F012 server access.
- [Current eligibility](../../../supabase/migrations/20261006185240_f011_publication_functions.sql#L3-L79) binds current admission status/validity/version and exact artifact/signatures. [Clinic status selection](../../../supabase/migrations/20261006185240_f011_publication_functions.sql#L947-L1001) separately checks current actor/facility authority, published/effective state, current eligibility and effective supersession. Its selected fields contain metadata, not rule bodies or a safety-consumer digest contract. [Eligibility interpreter](../../../services/api/src/modules/feature-011/content-eligibility.ts#L1-L11) trusts the authorized SQL projection; historical signatures alone are insufficient.
- [Verified evidence contract](../../011-allergies-clinical-content-governance/contracts/verified-evidence-binding-v1.md#L13-L23) separates immutable signed bindings from mutable current authority/expiry/revocation. A mock fixture contentVersion satisfies none of these conditions.

**Decision owner and stop:** Yousef must explicitly approve the engineering/product boundary; API Lead + Data Lead must reconcile the producer/consumer, current-authority, data/RLS and transaction contracts before Plan approval. Medical Director + Chief Pharmacist must provide clinical/source admissibility evidence under OPEN-CLIN-001/002; applicable Legal authority retains OPEN-LEGAL-003. Those release gates keep their canonical stages; missing engineering contracts separately block Plan approval. A necessary boundary or API amendment must be decided before Specify. No interface, endpoint, role, permission or eleventh operation is selected here.
