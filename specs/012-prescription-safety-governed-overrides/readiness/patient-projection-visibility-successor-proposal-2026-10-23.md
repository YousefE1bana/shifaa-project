## 2. Smallest proposed successor: V1–V8

**Recommended scope:** isolated synthetic F012 P/M projection only, under the two existing reads. First ask API/Data to produce a real already-approved source predicate if one exists. If none can be shown, the clauses below are a substantive new resource-specific disclosure policy needing separate approval/integration; they are not inferred from D3. No canonical file is changed here.

1. **V1 — explicit release fact and permission.** Patient visibility requires a versioned, resource/revision-specific explicit release decision for the P prescription and, independently, M statement projection; exact allowed audiences/field ceilings, policy/source version, attributable authorized issuer and current non-withdrawal must be provable. Propose granting only the current treating synthetic prescriber an additional narrowly scoped ability to request that release for their authorized prescription. Signing permission alone is insufficient. This release permission is **not established today**. No new role or patient relationship is proposed.
2. **V2 — carrier choice, separately approved.** Recommend an explicit optional release intent on existing signPrescription, with a separate deliberate confirmation and independently checked release permission; absence means no release. The sign outcome and any explicitly authorized release facts commit atomically. This changes the proposed operation body/authorization contract and needs a formal API/Data/Product/Security successor, not merely PO intent. No new endpoint, automatic signed=release, post-sign release/edit action or background default release. Already signed records lacking release remain denied; migration must not backfill inferred release.
3. **V3 — exact reader predicate.** Require native current actor/session/action/purpose, active actual subject, explicit current release for the requested resource/revision/audience, allowed status/field and actual source. PAT requires self mapping. GUA additionally requires current approved subject guardianship/evidence/purpose and existing allowed record fields; DEL requires current exact record.view permission/purpose/validity and allowed fields. Recommend release audiences explicitly distinguish subject, current authorized guardian, current record delegate; omitted audiences deny. A category release is per record, not blanket historical access. Product/Legal/DPO must explicitly accept managed-reader applicability; until then those audiences deny and remain blocked. No AAL2/facility membership is invented for PAT from workforce requirements; care/pharmacy keep their distinct native facility/AAL rules.
4. **V4 — exact field/status ceiling.** P: opaque prescription reference, status/version, actual signed/expiry/source-update times, permitted coded item product/ingredient/strength/form/route/dose/frequency/duration/quantity, non-sensitive source identity/version and explicit freshness/completeness/not_fully_checked. Only signed/cancelled/superseded/expired. M: opaque statement reference, actual product/status/start/end/source and known source version/update/freshness/completeness; optional item linkage independently authorized. Unavailable optional facts remain absent/unknown. No cancellation reason, indication, rationale/alternatives/monitoring, detected evidence, signer/person directory, synthetic classification, protected F011 data or supersession link in P/M. Every nested coding/source field still needs a necessity mapping. No source reference exposes a private storage path.
5. **V5 — source/withdrawal/currentness.** Release never proves source completeness/currentness or clinical safety. Record actual source identity/revision, observation/update time only when known, precise coverage and distinct missing/unavailable/stale/partial/freshness-unknown/verified-empty meanings. No guessed freshness duration/recent-use interval. Current withdrawal/policy changes and relationship revocation deny future reads immediately under an accepted participating currentness protocol. Propose controlled, audited offline synthetic source-policy withdrawal only if its real authorized writer/trust process is accepted; no existing installed withdrawal writer is claimed and no online release administration is introduced. Owners must settle this writer before acceptance.
6. **V6 — independent API and RLS.** API evaluates actor/action/subject/audience/source/status/field before composing P/M. Forced/default-deny non-owner RLS independently checks current native subject relationship AND exact release/source/status predicates. No clinical base-row grant from the new DTO. Field projections independently exclude private columns; SQL/repository and API each minimize. Direct raw non-owner requests without approved context deny; client-forged patient/role/AAL/release/GUC or JWT metadata cannot supply authority. Pagination binds actual reader/subject/purpose/filter and reauthorizes each page; revoked audiences receive no data/meta body. A read-only availability signal must not reveal hidden sources.
7. **V7 — immutable effects and provenance.** Proposed sign-time release is separate append-only evidence linked to exact signed version and, if P3 accepted, exact statement identity; no modification to signed content. Later cancelled/superseded/expired P view requires that same established release plus current permission, actual source status and field ceiling. It gains no new release through a status transition. Statement release cannot be inherited accidentally from an unrelated/new item/version. Release withdrawal preserves historical record, audit and original receipt while denying current disclosure; same-key sensitive replay still reauthorizes.
8. **V8 — scope/acceptance.** Existing twelve operations and D3 maxima remain; no new permission is effective before separately attributable successor approval and governed integration. Because this would supply new underlying release authority, it is outside the original D3 approval and must be explicitly reconciled with SPEC_APPROVED/contract bindings by their owners, not silently edited into spec.md. Real-patient/facility/legal release policy is excluded; Legal/DPO determine applicability and retain production gates.
