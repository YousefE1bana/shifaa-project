## 1. Problem and scope

### Problem statement

Within the isolated graduation environment, a synthetic prescriber must be able to prepare, check, correct and track a prescription; see incomplete evidence honestly; and follow independently reviewed normal or emergency exception journeys. Independent reviewers need minimal case discovery, explicit self-assignment and current case-bound decisions. Users need observable recovery from stale evidence, lost authority, competing actions and uncertain responses without losing immutable history or treating delivery as review.

### Actors and authorization context

| Actor                                                             | Facility/patient relationship                                                                                                              | Permitted outcome                                                                            | Explicitly prohibited                                                                            |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Synthetic prescriber / attending                                  | Current eligible care, originating facility, purpose, action and session                                                                   | Draft/check/acknowledge/request; separately guarded sign/cancel; authorized reads            | Self-approval, overriding a contraindication by acknowledgement, treating research as approval   |

## 3. User Scenarios & Testing _(mandatory)_

These are required outcomes and future verification obligations, not executed tests. Approved synthetic inputs carry no asserted diagnosis, severity or clinical correctness.

### Journey J-01 — prepare, check and correct

1. Given a current synthetic prescriber in an authorized F010 encounter, approved coded fixture inputs and explicit allergy/history/content provenance/completeness.
2. When the prescriber creates or updates a draft and requests safety checking.
3. The system binds the item/evidence revisions and exposes the actual mechanism result separately from overall clinical not_fully_checked; changed inputs invalidate affected reliance.
4. The user sees the reason, source/version, timestamp and allowed next actions; immutable audit records the operation. Q1 defines the evidence envelope, approved D1 T2+G sufficiency for bounded simulation only and source-derived atomic failure outcomes; overall clinical assessment remains not_fully_checked.

### Journey J-02 — warning acknowledgement and normal independent review

1. Given a mechanism warning or contraindicated issue bound to current evidence and an independent designated pharmacist.
2. A warning acknowledgement captures its required structured reason, justification and applicable monitoring; it never clears a contraindicated issue. For a contraindicated issue, the prescriber replaces/corrects it or requests governed review with rationale, alternatives, monitoring and expiry.
3. The normal request creates the pharmacist lane atomically. The reviewer discovers only minimum metadata, claims their own lane, obtains authorized detail and approves or rejects using current bindings.
4. Normal signing remains blocked without the required current independent approval. Sign is a separate prescriber action. Q2 applies approved W-M/W-NA/N/E logical contexts; rejection/expiry recovery is correction/check and a fresh linked request. No controlled/NTI flag chooses a context.

### Journey J-03 — emergency independent physician and immediate pharmacist obligation

1. Given an explicitly selected synthetic emergency pathway, distinct attending, second-physician and pharmacist persons, current designations and bound evidence.
2. The attending requests the emergency override; both lanes and the immediate durable pharmacist-review obligation are committed together.
3. A claimed second_physician approve decision is the sole mutation authorizing emergency **simulation**. It atomically binds the existing obligation and starts the approved 60-second virtual-clock scenario. There is no implicit prescription signature.
4. The prescriber separately requests signing under current guards. Pharmacist review may proceed before the second-physician decision; pharmacist rejection prevents authorization. Early pharmacist approval does not remove the emergency second-physician requirement. The browser cannot choose time/window.
5. Expiry without current pharmacist approval blocks continued simulated signing. An expired/cancelled/invalidated terminal case permits no late decision or reopen; an unreviewed obligation remains blocked metadata history. No real dispensing/administration is enabled.

### Journey J-04 — patient medication and prescription visibility

1. Given the subject or an already authorized current reader, with no reviewer grant inferred.
2. They read the permitted getPrescription/listPatientMedications projection.
3. They see actual source/status/provenance, freshness/completeness and prescribed versus genuinely supplied dispensed/active history; missing later-owner input stays missing.
4. Cancellation/supersession and not_fully_checked remain visible only within approved D3 fields/statuses and current source visibility. Patient copy uses understandable prescription/medication source language in both locales, preserving all six source-state meanings. Before PLAN_APPROVED, Architecture/API/Data/Product must demonstrate an actually authorized positive patient visibility path using existing predicates, or explicitly report the affected journey BLOCKED; default-deny alone is not positive visibility acceptance.

### Journey J-05 — uncertainty, authority loss and delivery recovery

1. Given a lost response, competing claim, revoked designation, stale evidence or failed notification after a committed request.
2. A retry of the original mutation uses the same idempotency key/body; authorized reads reconcile current state.
3. Reauthorization precedes stored response disclosure. A committed effect occurs once; changed-body replay conflicts; invalid current authority receives no sensitive stored payload.
4. A still-current held assignment permits read-only terminal decision recovery until expiry/release/invalidation/authority loss. Durable obligation discovery survives notification failure. Workers retry delivery and cannot convert acknowledgement into review.

### Invariants and concurrency

- Independence compares underlying person identities across accounts: requester/attending, second physician and pharmacist are distinct. Ordinary licences, pharmacy membership, medical_reviewer or service/admin status do not imply a lane grant.
- Every current read/action/replay evaluates native session, action/purpose, facility, care where applicable, isolated deployment/roster validity, lane independence and relevant evidence. Failure to establish authority denies reliance/disclosure.
- R1 discover returns only §6 metadata. Detail requires the caller's current held assignment/designation and exact evidence/request/assignment revisions. No care-facing getPrescription shortcut exists for reviewers.
- Request/assignment aggregate CAS and immutable clinical-evidence fingerprints are separate. Another lane's claim/decision advances aggregate concurrency state but does not invalidate unchanged evidence or the other lane's still-valid approval. It also does not permit using stale aggregate versions for the next mutation.
- Fingerprints bind exact prescription/items, allergy/history source/completeness, fixture/content digest, request, lane, assignment and roster/policy evidence. Material changes invalidate future reliance; historical signatures are never rebound to new evidence.
- Release, assignment invalidation or current authority loss denies future reliance immediately while preserving history. Terminal own readback is read-only and bounded by current held assignment, expiry, evidence and authority.
- Every mutation commits domain transition, assignments/obligations, append-only audit, outbox and canonical response/completed idempotency result atomically as applicable. Any required-write failure rolls all of them back.
- Same-key replay authorizes before returning the stored response. Same principal/route/key and different body yields 409 idempotency-key-reused. Sensitive stored responses are not returned after current authority loss.
- Claims/decisions/signing and revocation/invalidation must have a documented linearization order; independent-session races, stale versions, rollback and cross-lane cases require later raw evidence in contracted runtimes. No race result is asserted by Specify.

### createPrescription — POST /v1/encounters/{encounterId}/prescriptions

Current care prescriber; FR-SAFE-001/003 and prerequisite SAFE-009. Approved coded items, substitution allowance and expiry produce a draft plus bound safety result. Idempotent mutation; no invented patient data/medicine values. Q1 defines evidence-state outcomes; Q1-U2 requires failure without partial successful creation when the required safety result cannot be produced. Required audit/outbox/receipt commit atomically; no automatic signature or fulfilment.

### updatePrescription — PATCH /v1/prescriptions/{prescriptionId}

Current prescriber, eligible unsigned prescription; FR-SAFE-001/003. I,V: idempotency and If-Match. Item changes append a version/rerun safety and invalidate affected evidence/acknowledgement/approval reliance. No edit to signed bytes. Q1-U2 requires rollback of a failed required recomputation, preserving the prior committed version; actual changed evidence still invalidates future reliance. Q1/D1 and Q2/D2 govern evidence sufficiency/field applicability.

### runPrescriptionSafety — POST /v1/prescriptions/{prescriptionId}/safety-checks

Current prescriber; FR-SAFE-001/003. I,V; optional content-version selection remains the existing carrier and requires admissible source/current eligibility. Returns actual bound issues/check digest and completeness, never fabricated clearance. Clinical content is not made admissible by a research match. If no required result can be produced, invocation fails without a fresh successful check/digest; an old check is historical. Q1 applies.

### acknowledgeWarning — POST /v1/detected-issues/{issueId}/acknowledgements

Current prescriber; FR-SAFE-004. I; bind exact issue/evidence plus structured reason, justification and applicable monitoring. Returns immutable acknowledgement, not a contraindicated approval. Missing required data, wrong severity or stale issue cannot silently succeed. Scenario applicability remains Q2.

### requestContraindicatedOverride — POST /v1/detected-issues/{issueId}/override-requests

Current prescriber/attending in proper care/facility context; FR-SAFE-005/006/007. I; rationale, alternatives, monitoring, emergency selection, evidence and expiry bindings. Normal: pending pharmacist lane. Emergency: both lanes and immediate durable pharmacist obligation. Commit request/audit/outbox/receipt together or none; no automatic second signature or signing. Q2 retains exact approved scenario mapping.

### decideOverride — POST /v1/override-requests/{overrideId}/decisions

Current independent assigned pharmacist or second physician by pathway; FR-SAFE-006/007. I,V and exact lane/assignment/roster/evidence bindings. Only approve/reject; comment/signature digest and current authority bind immutable history. Second-physician emergency approval starts the virtual window atomically with obligation linkage; pharmacist rejection blocks authorization. No hidden activate/sign/request-information/referral action.

### signPrescription — POST /v1/prescriptions/{prescriptionId}/sign

Current care prescriber, AAL2/factor freshness; FR-SAFE-001/005/006/007 and retained SAFE-012 restriction. I,V. Separately rechecks current item/allergy/history/content completeness and eligibility, exact approvals/assignments/designations, rejection and time/window. Returns guarded simulated signed state or domain problem; no real clinical permission. Normal unresolved contraindication blocks sign. Approved D1 requires T2+G: a complete, approved, coherent current mechanism scenario, with explicitly declared zero synthetic history permitted only within that bounded envelope. Required missing/stale/partial/unavailable/unproven mechanism evidence cannot sign; overall clinical assessment remains not_fully_checked.

### cancelPrescription — POST /v1/prescriptions/{prescriptionId}/cancel

Current authorized prescriber; FR-SAFE-011. I,V; existing reason carrier. Appends cancellation, invalidates linked pending authority and preserves signed bytes/lineage. No case withdrawal/reopen API or deletion.

### getPrescription — GET /v1/prescriptions/{prescriptionId}

Existing current subject/authorized care/pharmacy projection; FR-SAFE-011. Returns only the approved D3 maximum logical fields/statuses in Q3 intersected with actual current authorization and established source visibility. Reviewer designation alone grants no care projection. Signed is not patient release; unlisted or unproven fields/states deny; no protected F011 content. Positive patient visibility proof or an explicit affected-journey BLOCKED disposition is mandatory before PLAN_APPROVED.

### listPatientMedications — GET /v1/patients/{managedPatientId}/medications

Existing current subject/authorized care projection; FR-SAFE-001. Existing status/cursor selectors return actual authorized medication statements and provenance. Distinguish prescribed from dispensed/active/completed/discontinued/expired/entered_in_error; do not create later-owner inputs. Q3 fixes exact authorized matrix/freshness/degraded display; patient route composition adds no operation.

### getOverrideReviewCases — GET /v1/override-review-cases

R1, view exactly discover or detail, within FR-SAFE-006/007 and minimum-disclosure requirements. The closed discover query is view, lane, scope=eligible|own and optional cursor/limit, with no detail fields. Detail accepts only view, overrideId, lane and expected requestVersion, assignmentVersion, evidenceRevision, with no discovery filters. Reject mixed/unknown/extra fields. Discover returns {data, meta} using §6 metadata only for current eligible/own scope; cursor binds actor/facility/lane/filter, default 25, maximum 100. Detail returns one necessary assigned-case projection/current revision/permitted actions and requires current held assignment/designation and exact case evidence/request/assignment revisions; stale binding conflicts with no old payload. Current own terminal readback is read-only and ends on release/expiry/invalidation/authority loss. Scoped blocked-unreviewed metadata does not authorize detail/action. Exact query types/necessity/cursor/error schemas remain pre-Plan work; no third view or bulk export.

### transitionOverrideReviewAssignment — POST /v1/override-requests/{overrideId}/assignment-transitions

R2, action exactly claim, release_own or takeover_invalid; I,V. Body fields are action, lane, expected requestVersion, assignmentVersion including explicit unassigned revision, rosterRevision and evidenceRevision; the path binds overrideId. Caller is assignee only, with no assignee/user field. Claim requires pending live case and no valid holder; release_own requires the current eligible holder (revoked authority cannot release) and removes own future access/reliance without undoing decision; takeover_invalid atomically proves invalid holder and never steals a valid assignment. No renew/assign-other/reopen/expiry extension. Return 200 with assignment reference/revision, request/evidence bindings, expiry bound, transition/receipt metadata and allowed actions, with no clinical case payload. All applicable assignment/invalidity-linkage/audit/outbox/receipt effects are atomic.
