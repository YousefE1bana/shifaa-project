## 4. Exact S1–S3/S5–S8 protocol candidate

1. **Declared scope and producer ownership (S1/S2).** Producer metadata defines required source/coverage, immutable current member identities, revisions, projection/filter and contract version. Maintain per-patient allergy generation, declared content-catalog generation (covering new applicable series), and each admitted medication-source generation. Tokens are opaque producer-owned values, not client timestamps. Zero-member collections require initialized producer proof and complete scenario coverage; never infer allergy-free/medication-free. T1 is bounded technical read completeness; T2+G adds the approved coherent synthetic scenario. Overall clinical assessment remains `not_fully_checked`.
2. **Admission before existing locks (S3/S5).** Initial bounded synthetic design uses one deployment-scoped database admission fence, created only by a future reviewed implementation. All relevant database source/authority writers and every F012 evidence-reliant mutation take an exclusive transaction lock on it **before idempotency, series/domain or authority locks**. Authoritative read/capture takes a shared lock; no lock upgrade. Coarse serialization is selected over premature scope sharding because all writer dependencies and empty scopes must be covered. This changes predecessor writer protocols and requires coordinated successor integration; an F012-only advisory lock does nothing. Table-row versus advisory-key representation remains an implementation choice with exact collision/absence/default-deny verification, not an installed object.
3. **Writer effect.** Within that same authoritative transaction, each source-changing writer mutates its source and advances relevant generations; rollback advances neither. Authority-only changes must conflict on admission even if no source generation changes. No-op/replay does not manufacture new domain effects. New source scopes are initialized under exclusive admission. Read replicas never supply guarded admission; no remote source is claimed inside this transaction.
4. **Capture/pagination.** Public callers retain their native read permission on every page. An authenticated, scope-bound producer token binds the collection generation and query/projection. Each page is authoritative and generation checked; changed generation rejects continuation and requires a fresh existing read/check. A final page alone is not coherent coverage. A future producer-internal scan may hold shared admission for its complete capture; long transactions must remain bounded. Cross-page token validation proves a declared set only if every writer participates. Prior F011 cursors are not upgraded by prose; exact producer transport acceptance remains required. No new public endpoint is necessary or authorized here.
5. **Guarded F012 use.** Prepare permitted immutable input and local receipt-crypto capability before locks. Start one transaction on the same authoritative PostgreSQL connection; acquire exclusive admission; reserve/lock original idempotency scope. If already committed, reauthorize current disclosure of the original resource/case and return the original protected receipt; do not rerun a safety producer, generate new source effects, or treat historical receipt evidence as current clearance. Otherwise lock required F011 domain rows in their approved rank order, then F012 prescription/predecessor/request/lane/assignment rows in deterministic UUID/lane order; then encounter, workforce, relationship/patient/person, consent/participant, governed-authority/roster rows; finally append audit/outbox/obligation/receipt effects. Candidate order between F011 domain and F012-only rows is valid only if no other participant acquires the reverse edge; manifest/lock-graph proof is mandatory. No lower-rank acquisition, network call or lock upgrade after admission. Existing row-lock ranks remain otherwise intact; the new fence is an explicitly proposed rank zero across participating transactions.
6. **Recheck and linearization (S6).** After locks, obtain server-authoritative time, resolve current native actor and every case/care/facility/purpose/designation predicate; compare exact source generations, current heads, eligibility and captured evidence digest; check aggregate CAS independently. Validate effective-from inclusive / valid-until exclusive boundaries against the owning contract (licence date semantics are not replaced with a new timestamp rule). Do not use transaction-start time for a late action. The conditional guarded domain effect is the proposed logical action linearization point; retain protection through receipt finalization and commit. Writer-first means old reliance fails; action-first means only that historical commit survives. Source generation alone supplies neither result.
7. **Time limitation.** Locks serialize writers, not the clock. Recheck current deadlines immediately before guarded effect and before final commit constraints; if an applicable deadline is reached, rollback all effects. No claim is made that a pre-commit SQL time check proves physical WAL commit occurred before a wall-clock deadline. If a consumer contract requires that stronger physical-commit cutoff rather than action-time ordering, the affected capability remains BLOCKED_MISSING_EVIDENCE until an actually enforceable accepted protocol is supplied. Virtual emergency time remains the separate versioned 60-second mechanism clock, never renewed by this fence.
8. **Native authority admission.** An Auth check outside the transaction is insufficient. Before enabling a dependent action, prove the authoritative native session/factor/recovery writers and required user-status predicates are ordered against the guarded effect. A separately reviewed lock-capable native authority port could be evaluated only if supported by actual pinned Auth writer behavior and narrow security-reviewed privileges. An application fence not honored by GoTrue cannot claim revocation ordering. No independent-service transaction or distributed atomicity is assumed. Missing proof blocks claim/detail/decision/sign or other affected current-authority-dependent paths; read denial cannot become success.
9. **Failure/retry (S7).** Unknown writer, absent source proof, required producer failure, stale/partial/unavailable source, mismatched current generation/revision, lost native authority or missing S4 admission fails closed. Required create/update/check result failure rolls back all required effects; previous committed unsigned draft and immutable history remain intact. A genuinely produced incomplete draft result remains distinguishable from producer execution failure. A deadlock/serialization retry starts a fresh transaction and fresh current guards with the original actor/key/body. No automatic lease/window extension. Uncertain commit is reconciled by the original key under current disclosure authority; never infer rollback from timeout, receipt-lookup failure or expiry. Original receipt bytes/status/headers are returned once authorized; failed receipt encryption/finalization rolls everything back.
10. **Atomic outcome/isolation (S6/S8).** Domain state, assignment/decisions, separate simulated signature, replacement lineage/P3 statements when applicable, durable emergency obligation, audit, minimal outbox, canonical protected response and completed idempotency commit together. Enforce deferred commit-obligation consistency as in the F011 receipt pattern; do not claim it installed for F012. No owner/service-role online bypass, protected F011 material, professional identities or new public operation. Scope admission and current G never approve executable rules or clinical sufficiency.

## 6. P1 technical realization

Approved Product policy: `requestExpiresAt <= createdAt + 30 minutes`, bounded by earlier applicable expiry; `assignmentEndsAt = min(claimAt + 5 minutes, requestExpiresAt, designationEndsAt, earlier authority invalidation)`. Required absent/unknown expiry or authority cannot be treated as infinity. Known unbounded designation is only acceptable if its accepted source explicitly permits it. Current request/assignment status, designation and native authority are checked at every guarded action.

Proposed technical contract: server database action clock sets creation/claim times; request expiry is immutable once created, assignment expiry immutable once claimed, equality is expired. A release ends own assignment and reliance; invalid holder may be taken over only through R2 `takeover_invalid`, under request/assignment CAS and current admission. R2 `claim` never steals a valid holder. `release_own` cannot release another actor. Fresh claim after valid invalidation creates new assignment identity/history; no renewal/replay/decision/heartbeat extends time. Request expiry is terminal; create a fresh linked request through the existing operation, preserving prior obligation/history. Future tests cover exactly-before/equality/after, waited locks, revocation versus takeover, two claims, same-key replay and stale CAS. Native ordering/roster writer proof remains required; this is not another Product-policy question.

## 7. P2 and P3 exact proposed technical deltas

### P2 replacement

The existing draft's optional naked `predecessorPrescriptionRef` is insufficient. Proposed **wire successor**, not an approved current API field: `createPrescription` optionally accepts a closed `replacementIntent` object containing `predecessorPrescriptionRef` UUID and `expectedPredecessorVersion` positive integer; both or neither. Body digest binds it. This changes the create request schema and needs governed API-contract integration; adding it does not create an operation or grant correction authority.

Server stores immutable intent; same synthetic patient and originating scope, signed replaceable predecessor, no self/cyclic link, and separate current authorization of predecessor and replacement are required at create and sign. Proposed minimum correction predicate is the original prescribing person with current treating/facility/action/purpose/AAL authority for both resources. That resource-specific correction predicate must be explicitly accepted in the API/Data successor; ordinary draft creation alone does not establish it. **BLOCKED_MISSING_AUTHORITY for actual correction access until effective acceptance.** No hidden administrator or other prescriber correction grant is inferred.

Create does not supersede or reserve a successful successor. Separate sign locks both prescription aggregates in UUID order under admission, checks predecessor expected version/current signed state/no successful successor, then atomically commits replacement signature, predecessor superseded transition, immutable lineage, P3 statements and all required audit/outbox/receipt effects. Uniqueness admits at most one successfully signed successor per predecessor. Failed replacement sign or any required write leaves predecessor unchanged; competing/stale/cancelled/already-superseded targets fail current CAS/state guards. Replays produce original effects only. Linked resources each require independent current authorization; no linkage implies patient release or grants successor visibility. Signed clinical bytes remain immutable; append-only state/history records supersession.

### P3 prescribed producer

APPROVED_PRODUCT_ARCHITECTURE trigger is successful F012 sign, not create/check/override approval. Proposed unique identity is `(producer=F012 sign, prescriptionId, signedRevisionId, signedItemId)` with immutable signed version/item provenance and statement identity. A unique constraint and deferred sign-commit obligation must require exactly one `prescribed` statement for each committed signed item and reject extra/missing/mismatched statements. Include source contract/version, signed resource/item reference, occurred-at and immutable provenance; do not put free clinical text in outbox/audit. Opaque IDs do not grant readers access.

Writer is the same named, currently authorized F012 signing actor through the guarded Core API application use case; future narrow non-owner SQL function/RLS may insert only statements derived from the same successfully signed aggregate. No general statement-write operation, owner/service bypass or client-selected status. This is an explicit proposed Data/RLS producer contract; no installed F012 writer is claimed. Failed/competing signing, missing item, unique collision, outbox/audit/receipt failure all roll back signature, lineage and statements together. Idempotent replay cannot emit again. Cancellation/supersession does not rewrite statements into `discontinued`, `active`, `dispensed`, `completed`, `expired` or `entered_in_error`; those producers remain separately unestablished. No patient visibility follows from P3. Required medication-source generation advances atomically so subsequent guarded reliance sees new prescribed records.
