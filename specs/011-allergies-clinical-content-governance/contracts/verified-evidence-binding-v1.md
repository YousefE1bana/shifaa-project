# Feature 011 verified evidence binding v1

Contract: **SHIFAA-F011-VERIFIED-EVIDENCE-BINDING/1**. Recovery draft, 2026-10-06; technical review required, not Plan/gate/implementation approval. This supersedes R2-SD-04 and AC-02/03/04 design omissions under [the dated decision](../decisions/plan-recovery-evidence-foundation-2026-10-06.md). [Machine profile](verified-evidence-binding-v1.json) closes the logical shapes; [fixed vectors](verified-evidence-binding-v1-vectors.json) specify admission outcomes. These are design inputs, not an implemented verifier.

## 1. Small shared foundation and trust boundary

A binding is an immutable verified association consumed by a named typed domain boundary. It is NOT a public operation, authorization/rules engine, medical ontology, generic physical evidence table, arbitrary JSON claims bag or boolean verified=true. The public reference is a selector, never authority.

Every closed logical result has contractId, profile, bindingId, producerId, verifiedAt and the profile's exact fields. UUIDs are canonical lowercase; integer versions positive; verifiedAt is service-generated UTC with six fractional digits; source IDs/references are exact nonempty UTF-8 without NUL. Digests are 64 lowercase hex only in profiles whose source already provides/requires one. No Unicode/locale normalization. Unknown/duplicate members, wrong profile or caller-authored trusted results deny before SQL. This is an internal logical schema, not a new signing-byte serialization; ARTIFACT/1 and all BODY/AAD bytes remain unchanged.

Profiles: content_material, code_material, test_vector_material, signing, credential, designation, signing_authority, admissibility, allergy_verification. Repeated concepts have the same meaning; fields are NOT forced onto profiles that do not need them. Artifact review consumes existing material bindings, not a new evidence type. Native session, current workforce/care, ADM-MEDICAL and status-read predicates stay their existing authorities, not evidence-port booleans.

Allowed producer IDs are fixed per profile in the machine profile and configured by the trusted repository; a client cannot select a producer/source/key. A provider/source identity is pinned by approved adapter configuration; an external verification result requires source contract validation, authenticated verification and immutable reference/correlation association. No provider, signature algorithm or registry is selected here. An absent/unavailable/unapproved source denies; synthetic producers are explicitly isolated and never real clinical approval. Trusted process compromise is not prevented by passing a producerId string to SQL: the existing verified repository credential/forced-RLS/narrow-function boundary admits it. Direct end-client SQL/trust-envelope creation is denied. SQL independently compares everything derivable from locked rows.

No raw material/document/verifier payload, clinical reason, key or secret appears in the shared result or durable sidecars. Existing authorized artifactReview strings and protected clinical/receipt payloads retain their precise exceptions, access and storage rules. No evidence body enters SQL as resolution input.

## 2. Three temporal concepts

1. Historical snapshot: exact evidence and authority basis supporting a completed decision. Immutable, never rewritten/deleted by revocation (production retention/holds remain gated, not a new infinite-retention policy).
2. Current eligibility: governed mutable database status/version/validity checked NOW, independently.
3. Domain decision: immutable outcome for an exact resource plus historical binding; it is not reinterpreted from unrelated current authority.

Current professional_licenses, designations and grants have mutable versioned rows, not an explicit safe successor lineage. Therefore **EXACT_BOUND_ROW_VERSION_ONLY** applies to all three. Publication/eligibility requires the historically bound row ID AND version still current and eligible, the same person/capacity/scope, and exact equality of captured eligibility fields. No new row, renewal version, regrant, replacement or revoke/reactivate version rehabilitates the signature. Even an otherwise benign version change requires a fresh decision. No same-lineage exception is claimed.

Preserve old signatures forever as history under applicable retention/holds. Existing one-final-decision-per-capacity/artifact rule remains: if a fresh signature cannot be appended for that artifact, create a new independently reviewed draft with the existing operation, rather than overwrite/re-sign in place. Current publication/selection denies missing/revoked/expired/version-changed basis and does not silently reactivate a superseded ancestor. Current-authority original-receipt disclosure is a separate check: a permitted new grant may allow reading one's original receipt, but NEVER converts that historical signature into current publication approval.

FKs reference stable current row IDs ON DELETE RESTRICT, not mutable (id,version) pairs. Historical versions/facts are captured in immutable typed columns. Narrow insertion compares snapshot versions/facts to SHARE-locked current rows; later updates may advance current versions without breaking FKs or erasing history. Governed writers must advance versions for any eligibility/evidence change; equality of stored basis fields also catches inconsistent same-version changes.

## 8. Coding validation ownership

OpenAPI requires substance identity/display and source, NOT coding; KnownUnknownCoding allows explicit unknown. No approved configured terminology/registry is identified in this repository's Feature-011 dependency corpus. Therefore current real capability accepts omitted/explicit unknown coding; a new caller-supplied knowledge=known coding without an approved matching validation source fails with existing redacted validation-failed, and the caller may explicitly resubmit unknown. Do not silently discard/convert supplied known values. Syntactic system/code validation is never terminology validation.

An approved configured terminology boundary is the ONLY producer that may assert externally validated known coding; its closed result binds exact system/code/display, configured source identity/version where defined and the prepared revision. This is a gated port capability, not a new terminology service/vendor or medical vocabulary. Synthetic source fixtures may exercise the known branch in an isolated synthetic environment, labeled mechanism evidence only. Real source absence cannot use those fixtures. No response field claims validation beyond the existing KnownUnknown value.

Unchanged previously accepted protected known coding is preserved during verification as historical reported/validated-at-creation data; no claim of fresh external verification and no silent downgrade. Explicit new/corrected known coding requires the approved source; explicit unknown remains permitted. Real-producer acceptance owns source approval/configuration, exact result association and no synthetic bypass. Source substitution/unavailable rejects before encryption/mutation; no registry call under locks. This conditional domain validation preserves the unchanged optional wire shape; it is not a mandatory coded-value product conflict.

Sidecars cannot be read through clinic DTO/SQL projections. Sidecar structural FKs/uniqueness and resource-consistency/deferred guards are physical evidence; trusted source authenticity is real producer evidence, not a new SQL cryptographic promise.

Discovery/preparation/material/verifier work happens outside locks. Existing rank: idempotency -> content advisory -> domain -> F010 encounter -> baseline workforce/admin -> care/patient/person -> consent/participant -> Feature011 current authorities/designation/admission AND needed immutable support rows -> audit/new immutable effects/receipt finalization. Needed immutable private_evidence_objects rows for credential evidence FKs are SHARE-locked at the end of baseline workforce/admin rank 5; all referenced people (reviewer/issuer/designator as well as actors) are discovered and locked at rank 6. Issuer revalidation means the bound issuer identity/evidence/independence plus current grant/designation validity; it does not infer a new requirement to recreate historical issuance from an issuer's later unrelated admin grant. Support rows use SHARE, consumed uniqueness is checked on insert; no post-audit domain/authority acquisition or external call. Offline provisioning conforms to the same ranks. A stale basis denies atomically; retries redo current preflight and reference validation, fresh domain ID/nonces where applicable. Reuse of an immutable unconsumed support reference is allowed only for the unchanged exact context; consumed refs deny except authorized stored-result replay.
