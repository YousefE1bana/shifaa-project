# Feature 011 authorized artifact-review disclosure

Recovery R2 design, 2026-10-06; review required, implementation paused. This resolves SD-01 under the [R2 decision](../decisions/plan-recovery-r2-2026-10-06.md), superseding the historical blanket no-caller-return sentence without rewriting that decision. Public OpenAPI and ARTIFACT/1 remain unchanged.

## Exact existing representation and integrity

OpenAPI `ArtifactReview` is a closed object with exactly `content`, `code`, `testVectors`, each an unformatted string. `GovernanceRelease` and `AssignedReviewRelease` require it; `StatusRelease` excludes it. There is no binary/base64 encoding indicator. The faithful existing representation is the exact Unicode string whose strict UTF-8 bytes are the resolved material. No base64 substitution, lossy replacement, trimming, newline conversion, BOM stripping, NFC/NFD normalization, locale conversion or parse/reformat of code/test-vector text is permitted. JSON transport escaping changes transport syntax only: decoding the JSON string and re-encoding UTF-8 must recover the exact resolved bytes and release-bound SHA-256. Empty material remains an empty string where the existing schema permits it.

Before accepting material for a release response or review, the Evidence Port must establish lossless UTF-8 decode/encode equality. Non-text/broken UTF-8 material cannot be represented by this unchanged schema; deny with the existing redacted evidence-dependency failure behavior and report a public-contract conflict if a required artifact actually uses such material. Do not silently encode it differently. The current fixed neutral artifact vectors are UTF-8 representable; this is not approval of any real material. The port may hash arbitrary bytes internally, but cannot claim arbitrary binary disclosure through this string DTO.

The trusted Evidence Port resolves each immutable content/code/test-vector reference, obtains exact bytes, recomputes SHA-256, and compares BOTH reference and hash to the release-bound verified evidence tuple. Missing, swapped, substituted or mismatching material denies the entire required projection; no partial success, alternative latest reference or digest-only response. Current reference possession is never authorization. The content material must also be the intended plaintext protected by the release BODY/1 producer; later real composition proves that association. ARTIFACT/1 binds these references/digests; signatures bind its immutable release/version/digest.

## Current authorization and lock boundary

Use existing `listClinicalContent` governance or exact-release `assigned_review` projection, and the existing required `artifactReview` in authorized create/publish response DTOs. No operation/route/field is added. Verify current action-specific governance authority or separately granted exact-release/artifact reviewer read authority, permitted purpose, required AAL2 and current reviewer/governance scope. Signing alone does not grant review access. Create/publish authorization must independently cover disclosure of their exact response artifact; absent disclosure authority denies before the mutation commits rather than dropping a required response field. No general draft access follows from a signature grant.

Reads use a short authorized metadata snapshot, resolve/verify material outside write/authority locks, then a short final authorization check before disclosure. Immutable release/reference/hash bindings are compared at that final boundary. Mutations pre-resolve/verify their exact response material before entering the lock-holding transaction; locked current authorization and immutable binding checks precede receipt construction/commit. No external material lookup occurs under database locks. Revocation completed before final authorization denies; ordinary trusted-native-session limitations remain as in the baseline. A whole page fails closed if any required artifactReview cannot be authorized or verified.

Completed receipt replay does not rebuild a body from current resource state. Fetch/authorize original receipt metadata first; prepare decryption and verify its bound immutable evidence outside locks, then reauthorize and decrypt/validate the original stored bytes at the final disclosure boundary. Compare the receipt's decoded review strings with the verified original reference/hash tuples. Return the original status/body/headers only. Verification is not response reconstruction and produces no new domain effect/encryption. Missing evidence or lost review authority denies replay even when a receipt exists.

## Allowed disclosure versus prohibited sinks

Raw material must not enter PostgreSQL as an evidence-resolution input, in any encoding; appear in clinic/status or unauthorized governance DTOs; or persist in generic platform receipts, audit, outbox, logs or telemetry. Raw material is transient service memory and disclosed only in the authorized existing artifactReview. It is never a SQL argument/result containing plaintext evidence material.

Required create/publish response snapshots include artifactReview. Their dedicated private `clinical.mutation_receipts` may contain ONLY ciphertext protecting the exact authorized canonical response under [receipt v1](mutation-receipt-v1.md). This is encrypted response storage, not raw evidence storage or a generic receipt exception. `platform.idempotency_records.response_body` carries only an opaque receipt pointer; no raw body or keyRef. Clinical-content BODY keyRef, material bytes and plaintext response never enter audit/outbox/telemetry. Receipt keyRef is private crypto-storage metadata, distinct from the forbidden exposure of BODY keyRef.

Clinic queries choose a closed metadata allowlist and must not invoke the material resolver/decryptor. Lack of authority never returns a reference-existence hint or material in a redacted error. Sensitive-read/access attribution follows the existing audit boundary without clinical values; replay does not duplicate the original mutation audit/outbox.

## Acceptance owners

- Contract preparation: unchanged public schema inventory; UTF-8/string roundtrip, delimiter/control/Arabic/NFC/NFD examples; non-UTF-8 denial. Hash expectations remain independent fixed inputs.
- Synthetic physical proof: closed clinic SQL projection, private receipt ciphertext-only storage, forced RLS and non-owner access denial; no raw material injected into SQL negatives.
- Real Evidence/Protection producer: missing/wrong-reference/wrong-digest/substitution failures; exact body/material correspondence; no DB calls carrying material; no prohibited-sink sentinel; authorized exact review strings and encrypted receipt composition.
- Application acceptance: current unauthorized reviewer, wrong release/artifact, stale grant/purpose/AAL, signing-without-read, clinic projection and replay after authority/evidence loss. Test no resolver/decryptor call for clinic/unauthorized access. No fixture establishes real-content approval.
