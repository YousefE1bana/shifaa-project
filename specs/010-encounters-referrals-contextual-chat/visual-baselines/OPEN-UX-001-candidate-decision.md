## Scope and privacy review points

- Patient `/records` alone offers referral preview and acceptance. The modal shows explicit opt-in or opt-out selection for optional source `encounter_type`; the two review fixtures represent an actor-selected choice, not a default. The representative review names the acting guardian role and managed patient inside the modal without inferring consent. The accepted state shows booked appointment ID, resolved doctor/facility/slot, authorized/shared disclosure, and an explicit **View appointment** action visible at 360×800. Server-priced EGP/cash terms are displayed without an editable payment control. Authority loss uses guardian/delegate context and hides patient data. Clinic `/referrals` creates/tracks internally; pre-creation review has no committed REF row/ID, the confirmation includes source encounter, and accepted status shows the linked booking/target.
- Patient `/encounters/:id` alone contains patient message composition. `access-ended` depicts the approved completed-encounter cause; no fixture shows self with an open encounter and unavailable chat. The compact completed view visibly states that contextual chat has ended. The private-note exclusion fixture is byte-identical to the patient-visible-only fixture at every locale/viewport pair, including its displayed evidence label. The message-success result appears in-frame at all three patient viewports. Clinic note draft shows body/type and an explicit `private|patient_visible` choice before signing; signed versions remain immutable.
- Clinic `/patients/:id/summary` shows **Start encounter** only with the linked `checked_in` appointment and `called` queue context, with a review modal and server recheck. Ineligible/stale state blocks the start; successful navigation is represented on existing clinic `/encounters/:id`. Its fresh `created` fixture shows one server-derived responsible clinician, empty signed notes and optional references, and the consultation/service transitions. Later encounter fixtures retain participant edit and explicit end confirmation, responsible-clinician non-removability, immediate message-access cutoff, and distinct atomic completion review. Completed team wording is historical. Medium-width clinic navigation uses visible text labels. Human-facing state and note-visibility labels are localized rather than raw enum codes.
- Clinic `/messages` requires a selected appointment context. Ended participation or completed context removes message history and composer. Stale/offline/reconnecting views hide clinical detail pending authoritative REST reauthorization. Message composition is body-only; no attachment UI appears.
- `listFacilityMemberships` is owner-scoped in the API Catalog and implementation; it is not an approved treating-clinician participant picker. No authoritative current facility-workforce read source was found for general clinician addition. The candidate therefore depicts deterministic participant end/remove only, with no add control or invented directory API. Arabic referral dates use localized `ar-EG` text rather than English month names.
- All names, references, note and message text are seeded synthetic examples. The candidate adds no route, API operation, permission, clinical state, general consultation channel, prescription/safety content, Feature 011 surface, or offline clinical write behavior.
