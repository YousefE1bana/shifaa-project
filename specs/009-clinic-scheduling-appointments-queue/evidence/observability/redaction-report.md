# Feature 009 privacy and observability checkpoint

## Evidence boundary

This T077 report covers synthetic graduation engineering only. The release-surface scanner reads production source under the app, API, worker, contract, design-system, observability, database migration, and client roots, plus every file under this feature's `evidence/` directory. That evidence set includes all 492 mapped actual UI PNGs and older synthetic captures. Test files and injected test-kit fixtures are excluded so the deliberately seeded canaries remain available to test redaction. Approved reference PNGs are outside the scan and were not read, written, or hashed.

The scanner checks exact UTF-8 canary bytes for a patient name, destination, raw reason, coordinate, bearer token, appointment detail, and high-cardinality identifier. It self-checks detection of all seven canaries in memory before reading release surfaces and fails on any match. Scanning PNG bytes covers literal byte content and metadata as stored; it does not OCR pixels or prove that every visible value in a screenshot is acceptable. The separate T076 rendered-state review covers selected screenshots and has its own limits.

## Operational hooks and gaps

The Feature 009 observability module defines a bounded `clinic_scheduling.operation` event vocabulary, exact API/worker operations, fixed result and outcome classes, scope classes, and latency buckets. Its outcome codes cover schedule and queue conflicts, idempotency replay, queue version conflict, delay declaration/supersession/replay, absence application/replay, and outbox pending/retry/dead-letter. The metric-label function admits only bounded surface, operation, result class, outcome, scope, and latency bucket values; IDs remain event correlation fields rather than metric labels. Focused SQL/API/restore evidence also checks denied mutations and transactional audit/outbox effects, and the synthetic restore report records worker replay and restore freshness.

No live Feature 009 telemetry emitter wiring, dashboard, alert rule, production log/trace sample, cache-server metadata dump, audit/outbox export, or operational threshold definition was found in this worktree. Spec §12 explicitly defers dashboard and alert extension to later approved planning. Therefore this checkpoint does not claim verified dashboards or alerts for latency, contention, replay, queue versions, delay/absence effects, outbox age/retry/DLQ, RLS denials, or restore freshness. The fixed event vocabulary and synthetic tests are implementation hooks only. Production monitoring acceptance and any vendor-dependent delivery evidence remain open; no production SMS, PHI, or provider receipt is asserted.
